# GitHub 源码与成片发布

源码仓库保留可编辑工程及重建说明。MP4、离线播放器、可编辑源码 ZIP 与字幕可作为 GitHub Release 附件分发，避免将渲染中间文件与大型生成产物写入 Git 历史。

## 源码范围

首次提交使用以下文件范围，并在提交前核对实际暂存文件：

```text
.gitignore
LICENSE
THIRD_PARTY_NOTICES.md
README.md
index.html
package.json
package-lock.json    # 如已生成，应一并提交
requirements.txt
requirements-voice.txt
src/
scripts/
docs/
fonts/
```

`fonts/` 中保留两款字体和两份 OFL 文本。`src/`、`scripts/` 与 `docs/` 只提交工程源文件及面向使用者的文档，不提交临时脚本、缓存或含本机路径的运行日志。可选旁白脚本和时间轴属于工程源码，合成音轨和运行报告属于 `out/` 产物。

`out/`、`.tools/`、`.deps/`、`node_modules/`、虚拟环境、凭据配置和本地编辑器状态均不进入 Git。本工程不需要分发 FFmpeg、浏览器或语音模型文件。

## 发布附件

- 可直接播放的最终 MP4。
- 与成片版本一致的双语字幕 SRT。
- 单文件离线播放器 HTML。
- 可编辑源码 ZIP；包含项目 MIT 许可、第三方声明和字体 OFL。

配音版与纯音乐版存在时，附件名称需清楚区分。Release 正文说明画面规格、声音版本、合成语音身份和许可证，并链接重建说明。不要将完整运行日志或含本机绝对路径的验证 JSON 作为公开附件；公开验证结论可直接概述检查对象与检查结果。

## 发布前核对

1. 根目录 MIT 许可、第三方声明和两份字体 OFL 均在提交及源码 ZIP 中。离线播放器中保留其嵌入代码和字体所需的许可文本。
2. 根据 README 从源码能够启动预览；语音生成若依赖系统功能，文档明确平台、语音和命令。
3. 最终 MP4 通过完整解码，字幕及配音时间轴与影片匹配；播放器的播放、暂停和跳转正常。
4. 提交清单仅含上述工程文件；不含本机用户名路径、访问令牌、环境文件、日志、依赖二进制或渲染分片。
5. 用最终文件更新源码 ZIP、离线播放器与 Release 附件，避免发布修改前的打包结果。

发布行为及上传结果以 GitHub 实际仓库和 Release 为准；此文档只是工程发布约定，不表示发布已经完成。
